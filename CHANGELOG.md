# Changelog

All notable changes to this project are documented in this file. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/).

Every pull request that changes consumer-visible behaviour, the release flow or the CI workflows adds an entry under `Unreleased` (one bullet, ending `(#issue, #PR)`), or carries the `skip-changelog` label. `just bump-version` moves `Unreleased` under the new version heading, and the Release workflow publishes that section as the GitHub release notes.

## [Unreleased]

### Added

- Release pipeline: `just bump-version` opens a version bump pull request that rotates this changelog, merging it tags the version (`vX.Y.Z`, or `vX.Y.Z-rc.N` for a prerelease), and the Release workflow publishes this section as the release notes, static musl `aegis`, `aegis-controller` and `aegis-agent` binaries for amd64 and arm64, and multi-arch `ghcr.io/jaoppb/aegis-controller` and `aegis-agent` images bundling the `docker`, `sops` and `tailscale` versions pinned by the flake. The flake exposes the same binaries and images as packages (#8, #47)
- Desired-state domain model and repository loader: `hosts/<host>/<stack>/compose.yaml` with an optional `aegis.toml` (`expose`, `update`, `tailnet_tags`, `state`) and the reserved `aegis/` directory load into typed hosts, stacks, policies and a compose summary (services, volumes, mounts, builds, env files). Every problem is collected as a typed error, and an unknown `aegis.toml` key is one of them (#12, #51)
- Architecture checks beyond layering, run by `just arch-check`: struct field count and private fields in every crate, wrapped primitives and first-class collections in `domain` and `application`, no tuple groupings, no bag names, a 1000-line file limit, no lint exceptions and exact workspace dependency pins. The domain, application and adapters crates now keep their fields private behind constructors and accessors, with value objects and collection types in place of primitives; an empty compose `image` is now rejected (#53, #54)
- Stack validation: sync-time rules over the loaded desired state reject a stack that mounts a relative path writable or missing from the repository, mounts an undeclared named volume, builds outside its directory (context, Dockerfile or additional context), uses `include` or `extends.file` (their contents are not validated yet), references a missing `configs`, `secrets` or `env_file` file, or has an `env_file`, secret file or stack-level `.env` that is not SOPS-encrypted (a format check, no decryption). Every violation carries its file and, where possible, its line; a rejected stack is left out of the desired state while the others still load, so the loader now returns the valid stacks and the rejections instead of failing on the first bad stack (#13, #61)
- Controller-agent API over the tailnet: the controller and the agent serve `GET /v1/health` on `AEGIS_LISTEN`, and every request is authenticated by resolving the peer with `tailscale whois --json` and checking its ACL tag (the agent accepts `tag:aegis-controller`, the controller `tag:aegis-agent`). Untagged, wrongly tagged and unknown peers get `403`, and a failed lookup gets `503`. The versioned wire types live in the new `aegis-api` crate, and `docs/tailscale-acl.md` has the ACL snippet (#15, #55)
- Agent reconcile: `POST /v1/reconcile` (a 7 to 64 hex digit commit in the body, controller-only; `400` for a bad commit, `403` for another peer, `502` when the checkout fails) makes the agent move its git checkout (`AEGIS_CHECKOUT`, fetched and checked out detached through the new `git` CLI adapter, reusable by the controller) to that commit, load and validate the stacks of `AEGIS_HOST`, and bring each valid one up with `docker compose -p aegis-<stack> -f compose.yaml up -d --build`, against a rootless or rootful `DOCKER_HOST`. Compose is always pinned to the stack's own `compose.yaml`, so `compose.override.yaml` is never merged, and built services get a commit-SHA image tag. One failing stack does not block the others and rejected stacks are reported as invalid and never deployed. Reserved `aegis/` stacks deploy only when named in `AEGIS_RESERVED` (empty by default), and `purged` stacks are skipped until #20. Each stack's `running`, `failed` or `invalid` status is the reconcile answer and is also posted, best effort, to the controller's `POST /v1/status` (`AEGIS_CONTROLLER`), a route the controller serves with #14. The agent image now ships `git` and `openssh`, and `docs/agent.md` documents the variables (#16, #58, #67)
- Fail-closed compose parsing: stack validation now rejects every YAML tag and any compose key Aegis does not understand (including `label_file`, `develop`, `build.ssh` and `build.cache_to`, which read host paths) with the dotted path of each one, instead of silently dropping them while Compose acts on them. Spec keys without host paths and `x-*` extension keys are still accepted, and so is one level of `<<` merge. This closes the `<<` inside a tagged node (`!override`) bypass (#56, #68)
- Per-host SOPS decryption on the agent: for each stack it deploys, the agent decrypts the stack's `env_file` entries, top-level `secrets` files and `.env` with its own age key (`SOPS_AGE_KEY_FILE`, `SOPS_AGE_KEY_CMD` or `SOPS_AGE_SSH_PRIVATE_KEY_FILE`; `sops` 3.9 or later) onto a tmpfs workspace (`$XDG_RUNTIME_DIR/aegis`, else `/dev/shm/aegis`, refused when it is not tmpfs or not a private directory of the agent), points Compose at the copies with a generated `-f` override and `--env-file`, and removes them after `docker compose up`, on success and failure. A file that cannot be decrypted fails only its stack, and the error never carries `sops` output or a decrypted value. A decrypted `.env` may not set `COMPOSE_*`, `DOCKER_*` or the variables Compose inherits. The agent also refuses, before running `sops`, a file that names any key group other than age (`kms`, `gcp_kms`, `azure_kv`, `hc_vault`, `hckms`, `pgp`), which would make `sops` contact an address the file's author chose with the host's credentials, and a secret path that leaves the stack directory. `AEGIS_CHECKOUT` must now be an absolute path, and the agent exits at start-up when it cannot remove the decrypted files an earlier run left. `docs/sops.md` documents the `.sops.yaml` `creation_rules` per `hosts/<host>/**` with a backup recipient (#17, #69)
- Tailscale OAuth adapter for the controller: it exchanges the OAuth client credentials for an access token, mints single-use, pre-authorized, non-ephemeral keys tagged from `aegis.toml`, and deletes a device by ID or by an unambiguous hostname. A key is minted only while the sidecar's state volume is empty, so restarts never create nodes, and the OAuth secret and keys never appear in logs, errors or `Debug` output (#18, #65)

### Fixed

- The static musl binaries build again: `nix build .#aegis-controller` crashed with SIGSEGV in a build script (first seen as `icu_normalizer_data`), on every machine, because `pkgsStatic` leaked `-static` into the glibc compiler that links the build scripts. The flake now unsets it for the build, and CI builds the binaries and images for amd64 and arm64 on every pull request (`just build-release`, the `Release Build` job) instead of only at release (#66, #PR)

### Changed

- Release tags are protected: the `tags-create` and `tags-immutable` rulesets on `refs/tags/v*` let only the release GitHub App create them and let nobody update or delete them, `release.yml` is only called by `tag-release.yml`, `tag-release.yml` pushes the tag with that App's token, and `just ruleset-check` and `just ruleset-apply` handle every file in `.github/rulesets/` (#49, #52)
